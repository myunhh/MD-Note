## Product contract

Keep the existing continuous Markdown page and PencilKit free ink overlay. Add real in-app rendered rich Markdown editing (including Korean IME), robust annotations following edited text, and insertable blank/Markdown study space. Text editing and handwriting share one document. Maintain existing search, outlines, bookmarks, images, math, code, paper styles, archive and PDF behavior.

1. Edit rendered Markdown in place with a keyboard, with an explicit text/pen mode available for reliable touch routing. New text persists to the actual `.md` file. Never save a parse failure, placeholder, or partially composed IME value over a document. Use coordinated atomic writes, surface failure, detect external edit conflicts instead of overwriting. Preserve unsupported Markdown/frontmatter rather than silently dropping it. Source editing may be available as a deliberate fallback, but a raw textarea alone does not satisfy rendered editing.
2. Annotations have stable identities and references to stable blocks plus text ranges/context; content hashes remain useful for external reconciliation, not the sole identity. Text edits, splits/merges, moves, undo/redo, save/reopen must preserve or safely detach attachments. Deletion or ambiguous external matching preserves the original strokes and requires reattachment rather than silently discarding or randomly attaching.
3. Underlines/highlights in follow-text behavior project onto the target range's current line fragments. Free handwriting, formula workings, and graphs default to preserving shape as a group, translated with their target. Do not automatically distort arbitrary strokes or misclassify circles/arrows. Expose a practical selection or behavior control; do not claim arbitrary ink understanding. Keep original stroke data; projection must not accumulate transforms on every layout pass. Do not rebuild the drawing while Pencil is down.
4. Insert blank study space or a Markdown supplement at the selected/current block boundary. Allow editing the Markdown, resizing, moving and removing the space with undo. Default insertion reserves actual layout height and pushes following text and attached ink downward. Optional floating supplement can anchor to a block but may not obscure content without an explicit choice. All additions use the same page/scroll coordinate system and can themselves carry ink. Do not create a new WKWebView per note.
5. `.md` remains the text source. Study additions and original ink can use the existing `.md.inknote` companion with a backward compatible schema upgrade. Reopen, archive roundtrip and export must include additions; PDF uses the composed layout. Existing v1 sidecars remain readable and migratable without discarding orphan ink. A future schema is read-only. Preserve coordinated save/recovery behavior and stable IDs across reload.
